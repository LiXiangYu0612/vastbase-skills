# 案例：根分区 ENOSPC 压垮实例（env-A，2026-10）

## 环境

- env-A 测试机：CentOS 7（内核 3.10.0-1160），2 核，根分区承载实例数据与
  日志；双实例形态（5432=VastBase、8432=PG17）
- 时间线：2026-10-21 夜间发生

## 症状

- 实例被"压垮"：表现类似崩溃/不可用；清理 4.3G 测试镜像文件后空间恢复，
  但实例状态仍异常，当晚未能自动完全恢复（次日处理）

## 排查链

1. 实例异常 → 先按 `crash-panic` 分诊：**无 core、dmesg 无 OOM kill 记录**
   → 排除 OS 杀进程与段错误两条路
2. 查 pg_log：**日志写不进/截断**（写文件路径直接报错）——写失败即指向
   空间或权限
3. `df -h`：根分区 100%（占用大户=累积的测试镜像与产物，4.3G+）
4. 清理 4.3G 测试镜像 → 空间恢复，但实例未能自愈 → 走启动排查路径处理

## 根因

根分区 ENOSPC 挡住日志/xlog 写路径——数据库对"写不进日志"的响应是停摆
而非继续运行（正确行为：宁可停不可丢数据）。对照机制：
`../troubleshooting/startup-failure.md` 第 4 步（磁盘满=ENOSPC 排查位）、
`../troubleshooting/crash-panic.md`（"空间/硬件拖死"形态——崩溃只是症状）。

## 处置与结果

清空间 → 重启/恢复实例 → 恢复。教训：**先取证三件套再动**在本案例里
同样成立（日志与 dmesg 先存档，确认无 core/OOM 后才清理）。

## 预防

- 数据/日志/xlog 分区与根分区分离；根分区加容量监控告警（<10% 告警）
- 测试产物的落盘位置约束（不进根分区）+ 定期清理任务
- 巡检清单项：`df -h` 数据目录/xlog/pg_log/根分区四点
